# Onboarding

This skill replaces the old "FILL marker" auto-flow with an explicit
user-invoked walkthrough. It runs only when the user types `/onboard`.

## Pre-flight check

Before asking anything:

1. Read `CLAUDE.md`. Are there `<!-- FILL` markers? If no markers, the
   project is already onboarded — confirm with the user before
   re-running (re-onboarding overwrites prior choices).
2. Note which sections still need filling. Skip questions for sections
   the user already filled.

## The 7 questions

Ask these via AskUserQuestion (multi-question form when possible). Always
let the user pick "Other" for free text.

**Q1 — Project type**
- Code (web app, library, CLI tool, frontend) — *no automation module*
- Automation/ops (data pipelines, scripts producing JSON, cloud
  deliverables) — *imports automation-ops module*
- Mixed — *imports automation-ops module*

**Q2 — About the project**
Free-text. Project name, purpose, target users, key features. Used to
fill the "About This Project" section.

**Q3 — Tech stack & commands**
Language, framework, key dependencies, runtime version. Then: install,
build, test, lint, run, deploy commands. Propose sensible defaults
based on stack (e.g., `pytest` for Python, `npm test` for Node) and
ask the user to confirm or override.

**Q4 — Code style**
Formatters (black/ruff/prettier), naming conventions, import order,
team preferences. Use defaults for the chosen stack if the user has no
preference.

**Q5 — Architecture**
Free-text overview. For automation projects, suggest the 3-layer
directives/tools/deliverables description. For code projects, suggest
the standard layout for the chosen framework.

**Q6 — Caution-vs-speed bias**
- Karpathy-strict (default) — bias toward caution, ask before assuming,
  surgical changes, verifiable success criteria. Best for
  production/team code.
- Prototype-fast — relaxed think-before-coding rules during exploratory
  work. Surgical and verifiable rules still apply. Use for spikes,
  research, throwaway code.

**Q7 — Deliverable mode**
- Local-only (code stays in repo, no external services)
- Cloud-first (deliverables go to Sheets, email, databases — irreversible
  actions need confirmation per the universal rules)
- Mixed (case-by-case)

## Cross-tool support (sub-question, conditional)

After Q7, ask one more:

**Q8 — Cross-tool support?** "Will you use this project with anything
other than Claude Code (OpenAI Codex, Cursor, Windsurf, Aider, Gemini)?"

- No (default for 90% of projects)
- Yes → invoke the `/enable-cross-tool` skill at the end of onboarding.
  That skill handles the file generation and pre-commit hook.

## Apply the answers

Generate a diff for `CLAUDE.md` and present it to the user before
writing. Use the structure below. Get explicit confirmation.

### Apply the caution bias (Q6)

If the user chose **Prototype-fast**, append this line to the Universal
Rules section:

```
- This project runs in **prototype-fast mode**: relax the
  think-before-coding rules in coding-behavior.md for exploratory work.
  Surgical-changes and goal-driven-execution rules still apply.
```

### Scaffold for automation projects (Q1 = Automation or Mixed)

Create these directories (with `.gitkeep` files where empty):
- `tools/`
- `schemas/`
- `logs/`
- `.tmp/`

Write a stub `tools/validate_schema.py`:

```python
#!/usr/bin/env python3
"""Validate JSON output against a JSON schema. Stub generated by /onboard."""
import argparse
import json
import sys

try:
    import jsonschema
except ImportError:
    print("Install jsonschema: pip install jsonschema", file=sys.stderr)
    sys.exit(2)


def main() -> int:
    p = argparse.ArgumentParser()
    p.add_argument("--data", required=True)
    p.add_argument("--schema", required=True)
    args = p.parse_args()
    with open(args.data) as f:
        data = json.load(f)
    with open(args.schema) as f:
        schema = json.load(f)
    try:
        jsonschema.validate(data, schema)
    except jsonschema.ValidationError as e:
        print(f"Schema validation failed: {e.message}", file=sys.stderr)
        return 1
    print("OK")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Update `.gitignore` if `.tmp/` and `__pycache__/` aren't already covered.

## Hand-off

After applying:
1. Show the user a summary of what changed.
2. If Q8 = Yes, invoke `/enable-cross-tool` now.
3. Suggest next steps: "Run `/commit` to make your first commit, or just
   start a task."

## Idempotency

If the user runs `/onboard` again on a fully filled CLAUDE.md, ask
whether they want to:
- Update individual sections (re-ask only the chosen ones)
- Reset everything (write fresh from FILL markers — destructive)
- Cancel

Default to update-individual.
