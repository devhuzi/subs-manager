# Disable Cross-Tool Support

User-invocable. Companion to `/enable-cross-tool`.

## Detect what's installed

Check for:
- `AGENTS.md`
- `GEMINI.md`
- `.cursor/rules/project.mdc`
- `tools/sync-agent-files.sh`
- `tools/install-git-hooks.sh`
- `.git/hooks/pre-commit` (and whether it contains the sync logic)

Show the user a list of what was found.

## Ask what to remove

Use AskUserQuestion (multiSelect):
- Specific generated files (per file)
- The sync script (`tools/sync-agent-files.sh`)
- The hook installer (`tools/install-git-hooks.sh`)
- The pre-commit hook itself

Default: remove everything related. Let the user un-tick items they
want to keep.

## Remove the pre-commit hook (carefully)

The hook may contain unrelated logic the user added later. Before
deleting:
- Read `.git/hooks/pre-commit`
- If it ONLY contains the sync logic generated by `enable-cross-tool`,
  delete the file.
- If it contains anything else, surgically remove just the cross-tool
  block. Show the user a diff before saving.

## Confirm before deleting

Show a list of files that will be deleted. Get explicit confirmation.
Deletion is reversible only via `/enable-cross-tool` (which regenerates
from CLAUDE.md).

## Run

Delete the chosen files. Update the README if it has a "Cross-tool
support" section — remove that section.

## What you do NOT do

- Don't touch CLAUDE.md. It's the source; cross-tool support being
  removed doesn't change the project's authoritative rules.
- Don't delete `tools/` directory entirely — other tools may live there.
  Only delete the specific files this skill installed.
- Don't run `git add` or commit. Let the user review and commit.
